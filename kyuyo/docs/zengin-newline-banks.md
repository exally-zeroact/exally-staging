# 全銀（FBデータ）の改行コード — 銀行ごとの対応表

**なぜこの表があるか**：全銀協規定形式の「総合振込」ファイルの改行は **銀行ごとに違う**。
CR+LF／CR／LF／**改行なしの固定長** まである。
だから **1つに固定してはいけない**。
「LFの銀行に弾かれた」＝「CRLFが間違い」ではない。**今 通っている銀行を壊さない** のが最優先。

- Kyually の既定は **CR+LF**（`kyuyo/lib/zengin.js` の `NEWLINE_DEFAULT`）。
  ＝ 設定を触らない会社の振込は **1件も変わらない**。
- 会社ごとに **設定 ▸ 振込タブ ▸ 委託者情報 ▸ 改行コード** で `CR+LF / 改行なし / LF / CR` を選べる。
- 空・未設定・知らない値は **必ず既定（CR+LF）へ倒す**（黙って LF にしない）。

### この表から分かったこと

1. **CR+LF は調べた11行すべてで通る形**（明記あり8行・「改行あり＝標準」2行・楽天のみ記載なし）。
   → **既定を CR+LF から動かす理由は無い。**
2. **「LF のみを要求する銀行」は一次情報では見つからなかった。**
   世の中で起きているのは逆で、**LF だけのファイルが弾かれる**（CR+LF を期待される）事故のほう。
   ただし全銀の規定上は LF も認める銀行が多いので、**選べる形だけは用意**しておく
   （銀行から指定された時に、その会社だけ変えられる）。
3. **「改行なし」を要求／前提にする銀行は実在する**（楽天銀行）。JAバンクは CSV だけ改行必須。
   → 追加すべきだったのは **LF固定ではなく「改行なし」**。

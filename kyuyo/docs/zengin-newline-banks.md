# 全銀（FBデータ）の改行コード — 銀行ごとの対応表

**なぜこの表があるか**：全銀協規定形式の「総合振込」ファイルの改行は **銀行ごとに違う**。
CR+LF／CR／LF／**改行なしの固定長** まである。だから **1つに固定してはいけない**。
「LFの銀行に弾かれた」＝「CRLFが間違い」ではない。**今 通っている銀行を壊さない** のが最優先。

- Kyually の既定は **CR+LF**（`kyuyo/lib/zengin.js` の `NEWLINE_DEFAULT`）。
  ＝ 設定を触らない会社の振込は **1件も変わらない**。
- 画面では **振込タブ ▸「銀行に取り込めなかった時」（普段は閉じている）** の中で
  **銀行を選ぶ**と、この表から改行が決まる。開かなければ CR+LF のまま。
- 空・未設定・知らない値・**未確認の銀行**・一覧にない銀行は **必ず既定（CR+LF）へ倒す**。
  ★「未確認」は「変える理由が無い」という意味。黙って別の形にしない。★

**★この表と `kyuyo/lib/zengin.js` の `BANKS` は機械で突き合わせています**
（`kyuyo/tests/zengin.test.js`：名前・改行・出典URLが1つでも食い違えば赤）。

## この表から分かったこと

1. **CR+LF は調べた12行すべてで通る形**（楽天のみ「改行は不要」＝改行なし前提）。
   → **既定を CR+LF から動かす理由は無い。**
2. **「LF のみを要求する銀行」は一次情報では1行も見つからなかった。**
   世の中で起きているのは逆（**LF だけのファイルが弾かれる**）。
   ただし規定上 LF を認める銀行が多いので、**選べる形だけは用意**しておく。
3. 追加すべきだったのは **LF固定ではなく「改行なし」**（楽天銀行）。

## ★覚えておく軸（今は作らない）★

伊予銀行の手引きに **「１２０バイトの内に含めることも、含めないことも可能です」** とあります。
＝ **「118バイト＋CRLF で合計120バイト」を求める銀行が有りうる**という意味（レコード長と
データ長を別に指定する形。伊予銀行は5パターンに対応）。

- **今の Kyually の作りは「120バイト＋CRLF（＝データ長122）」**＝伊予銀行の5パターンのうち②。**通ります。**
- **他行から「120の内に改行を含めろ」と言われた時に初めて作る。今は作らない。**
- ここに1行残しておくのは、後で「そんな軸があったのか」とならないため（2026-08-09 決定）。

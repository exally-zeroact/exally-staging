## 1. ★実Excelで測った（COM で実際に固定した）★

| 選んだセル | 上に固定される行 | 左に固定される列 |
|---|---|---|
| B2 | 1 | 1 |
| A2 | 1 | 0 |
| B1 | 0 | 1 |
| C4 | **3** | **2** |

**⇒ ★選んだセルの「上の行」と「左の列」が固定される★**

- 先頭行の固定 = 上に1行 / 左に0列
- 先頭列の固定 = 上に0行 / 左に1列
- **★固定しても 合計は変わらない★**（見た目だけ）

### ★真似ない事（測ったけれど 真似られない）★

**A1 を選んで固定すると 実測は「上に9行 / 左に10列」**。
これは **今 見えている範囲の真ん中で割る** 動きで、**画面の大きさで数が変わる**。
同じ数を焼き付けても **画面が違えば 違う所で固定される＝真似ても合わない**。

**⇒ うちは A1 を選んで押した時は ★固定せず 理由を出す★**
「固定したい行の1つ下・列の1つ右を選んでね」

## 2. ★作り方（ここが 今までの3つと違う＝画面の描き方に触る）★

並べ替え・オートSUM・絞り込みは **データを触るだけ**だった。
枠の固定は **★画面の描き方（_doRender）に触る★**。ここは アプリの心臓なので、
**★他の物と混ぜず 1つだけの commit にする★**。

### 今の作り

```
 rowY(r) = HDR_H − scrollTop + r×行の高さ（＋高さを変えた行の分）
 yToR(y) = その逆
 _doRender() … 見えている行と列だけを 上から順に描く（240行・何回かに分けて塗る）
```

### 直す所（3つだけ）

| 何 | どう直すか |
|---|---|
| **① 座標** | `rowY(r)` … **固定した行（r < freezeRow）は scrollTop を引かない**（いつも同じ場所）。<br>固定していない行は **固定した分の高さを足してから** scrollTop を引く。`colX` も同じ。 |
| **② 逆引き** | `yToR(y)` … 上の帯の中なら 固定した行から探す。下なら 今までどおり。`xToC` も同じ。 |
| **③ 描く順と はみ出し止め** | 固定していない行が **固定した帯の上に重なって描かれる**ので、<br>**★4つの区画に分けて clip する★**（左上＝固定×固定／上＝固定行×流れる列／左＝流れる行×固定列／右下＝流れる×流れる）。 |

**★③が一番 危ない★**。今の `_doRender` は「1回ぜんぶ描く」形なので、
**★セルを描く所を 1つの関数に切り出してから★** 4回 呼ぶ形にする。
切り出しは **見た目を1ピクセルも変えない**（切り出しただけの状態で 実物のスクショを撮って見比べる）。

### 入口（★Excel と同じ場所に置く★）

Excel は **表示タブ > ウィンドウ枠の固定**。うちにタブは無いので **右クリック**に置く:

```
  🧊 ここで固定（選んだセルの 上と左）
  🧊 固定をやめる          ← 固定している時だけ出す
```

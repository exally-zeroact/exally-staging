# SPEC — E1 スイートの器（ハブ・共有データ・集計の骨）

Exally実装セッション作成。ROADMAP_Exally の **E1**。前提＝E0（`SPEC_shared_schema.md` v2・実装済/push済 3196df1）。

## 0. スコープ（経営セッション判定 2026-07-25 に沿う）
**E1 ＝ Exally自身の器**。`pay_org` / `pay_ledger` / `pay_partners` ＋ `pay_employees` の**読み**だけで完結し、
**Kyuallyの保存に依存しない**（Kyually P0 が直る前でも実機検証できる）。
「ハブ→給与（Kyually）の一気通し」は**後の統合マイルストーン**（Kyually P0 修正後）。

### やらない（E1では作らない）
- 日次台帳の**入力UI**（＝E2）。E1は台帳を**読んで集計する**だけ。
- 「きく」（＝E3）。差し込む**余地だけ**空ける（後でボタン1個を足せる場所を確保）。
- 請求・見積の実装（差別化モジュール・後）。
- 既存ページ（book/chat/template/seikyusyo/mitsumoriyo/kyuuryoumeisai）の**削除**。触らない。
- 凝ったグラフ（散布図など）。**読める一覧＋横バー**だけ。

## 1. 画面（モバイル前提・1画面ずつ・大きなタップ）

### 1-1. ログイン（オーバーレイ）
Supabase auth（メール＋パスワード／新規登録）。Kyually の `js/auth.js` と同じ流儀・同じ倉庫・**同じアカウント**。
- 未ログインでは中身を1バイトも出さない。
- `exally_entitlements`(app=`'suite'`) を見て、`disabled` なら**ロック画面**（アプリを触らせない）。
  行が無ければ `trial` を1行自動作成（E0の `entitlements.ensure`）。
- 判定は純関数 `lib/access.js`（plan → 使える/停止）。

### 1-2. ハブ（＝トップ）
```
┌────────────────────────────┐
│ Exally            ログイン中: xxx@ │
├────────────────────────────┤
│  こんにちは。今日やることは？          │
│                                      │
│ ┌──────────┐ ┌──────────┐ │
│ │ 💰 給料明細   │ │ 📒 日次台帳   │ │
│ │ Kyually       │ │ 準備中(E2)    │ │
│ │        開く → │ │               │ │
│ └──────────┘ └──────────┘ │
│ ┌──────────┐ ┌──────────┐ │
│ │ 📊 集計       │ │ 🗂 共有データ  │ │
│ │ 事業別に見る  │ │ 会社/人/取引先│ │
│ │        開く → │ │        開く → │ │
│ └──────────┘ └──────────┘ │
├────────────────────────────┤
│  🏠ホーム   🗂データ   📊集計         │  ← モバイル下部タブ
└────────────────────────────┘
```
- **タイルは4つだけ**（増やさない）。
- 「日次台帳」は**準備中と正直に出す**（押しても偽の機能を出さない＝捏造禁止）。
- 「給料明細」→ `https://payslip-app-olive.vercel.app`（実在を確認済み・別タブ）。同じログインなので入り直し不要。

### 1-3. 共有データ（3つ・タブ切替）
```
[ 会社 ] [ 人 ] [ 取引先 ]
```
**会社**（`pay_org`）：屋号／住所／電話／インボイス登録番号／**事業の一覧**（集計のグループ源）。
　　印影は E1 では出さない（請求・見積を作る時に足す＝使わない物を先に作らない）。
**人**（`pay_employees`）：**読みは全部・書くのは `employmentType` と `business` の2つだけ**（E0のallowlist）。
　　- 一覧＝氏名／雇用形態／事業。行をタップ→その2つだけ変えられる。
　　- 給与の項目（基本給など）は**表示もしない**（Kyuallyの担当・二重管理を作らない）。
　　- 人の**追加/削除はしない**（従業員マスタの唯一の源はKyually側の登録。ここは"タグ付け"だけ）。
　　- 保存時に `pay_companies.updated_at` を空更新（E0 §2-2・Kyuallyの巻き戻し防止）。
**取引先**（`pay_partners`）：名称／敬称／住所／インボイス番号。追加・編集・削除（ソフト削除）。

### 1-4. 集計（事業別・E1の"骨"）
```
期間  [ 今月 ▼ ]  2026-07-01 〜 2026-07-31
─────────────────────────────
事業        件数    売上        構成比
代行         42   ¥420,000  ████████████ 62%
空調         18   ¥210,000  ██████ 31%
未分類        3    ¥48,000  ██ 7%
─────────────────────────────
合計         63   ¥678,000
```
- 期間＝**今月／先月／期間指定**の3つだけ。
- 事業の決まり方（優先順）：**台帳行の `business` → その人の `business` → 「未分類」**。
- **読める一覧＋横バー**のみ。散布図・円グラフは作らない。
- **0件のときは正直に空を出す**（「台帳にまだ記録がありません」＋台帳は準備中と明記）。数字を作らない。
- 台帳が期間内に多すぎて全部読めない時は、**合計を出さずに「期間を短く」と出す**（E0の切り捨て検知）。

## 3. ドリフト対策（コピペ禁止の趣旨を守る）
`lib/access.js` は Kyually にも同じ物がある。別リポジトリなので import できないため、
**テストで両方を読み込み、全 plan 値（trial/paid/free/disabled/未知/null）で判定が一致することを検証**する。
payslip-app が同じマシンに無い環境では**スキップしたと明示**する（黙って緑にしない）。
※法定値・給与計算には一切触らない（Kyuallyの担当）。

## 4. テスト（2層＋実機）
1. **純関数**：`aggregate`（事業の優先順・0件・切り捨て・合計の一致）／`access`（全plan）／ドリフト突合。
2. **jsdom UI**：ログイン→ハブ→各画面→戻る、**全ボタンを押して例外0**。
3. **実機（Playwright・実ブラウザ）**：E0のテスト専用アカウントで、
   台帳にテスト行を入れる → 集計が正しい数字で出る → 全ボタン操作 → **console error 0** → 片付け。
   ※本物の従業員データが入ったアカウントは使わない（E0と同じ歯止め）。

---

## 5. 段取り（このマイルストーンの進め方）
1. **画面の形を見せてOKをもらう**（＝今ここ）
2. テスト先行 → 一気実装 → 対立監査
3. **実アプリを実ブラウザで実スクショして見せる**（別HTMLを自作しない）
4. **OK後に1コミットでpush**
5. トップ（`/`）の切替は**別途OKをもらってから**（`vercel.json` の rewrite を `home.html`→`hub.html`）。
   旧 `home.html` は**消さずに残す**（すぐ戻せる）。

## 6. 決めたこと（司さん判定 2026-07-25）
1. **既存ページ（ブック／AIチャット／テンプレ／請求書／見積書／給料明細テンプレ）はハブに出さない**。
   スイートのデータと繋がっていない物を器に混ぜない（看板撤去の趣旨）。**ファイルは消さない**のでURL直打ちで今まで通り使える。
   - ★但し書き（司さん）：**司さんが今この請求書/見積書で実際に請求しているなら「請求書と見積書だけ出す」に変更**する。
     変更コスト＝ハブにタイル2つ足すだけ（安い）。実請求に使っているかは司さんしか知らないので、**使っているなら一言ください**。
     それまでは出さない前提で作る（勝手に足さない）。
2. **トップ（`/`）は E1 の実機OK直後に新ハブへ切り替える**。ただし下記 §6-1 の条件を満たした時だけ。

### 6-1. トップ切替の条件（全部満たしてから切り替える）
| 条件 | 状態 |
|---|---|
| ハブに**本物の行き先が最低1つ**ある（＝働くKyually給与へ繋がる） | 給料明細タイル → `https://payslip-app-olive.vercel.app`（**実際に叩いて 200 を確認済み**） |
| 未完成の物は**正直に「準備中」と出す**（使えると嘘をつかない） | 日次台帳＝「準備中」・請求/見積＝ハブに出さない（＝嘘をつく面が無い） |
| ハブが**全部準備中の壁**になっていない | タイル4つ中**3つが本物**（給料明細・集計・共有データ）。壁にならない |
| **画面を見せてOK**をもらってから push | §5 の段取り通り |

★もし実装の結果ハブが「準備中だらけの壁」になったら、**その時は切替を E2 完了後に倒す**（司さん判定）。

### 6-0. ★実施済み（2026-07-25）★
- E1 本体 push＝**736f4ab**（`hub.html` 追加・front door は未変更）。
- front door の flip＝**5969c1c**（`vercel.json` の `/` と `/index.html` を `/hub.html` へ）。
  経営セッションが本番 `exally.vercel.app/hub.html` で確認しOK：4タイル（3本物＋日次台帳は準備中）／
  給与タイル→働くKyually実リンク／ミント `#F0FAF4` ＋ Noto Sans JP。
  DM Mono はロゴ（500・letter-spacing -0.5px）と金額に**適用済**＝Kyuallyと同一（実測確認）。
- ★承知の上の変更：**切替後は匿名訪問者にいきなりログイン画面**が出る（旧 home.html の説明は表に出ない）。
  pre-launch のため許容。**公開用の「価値を売るランディング → ログイン → ハブ」は今回のスコープ外・別途**。

### 6-2. ★rollback 手順（トップ差し替えを1分で元に戻す）★
1. **旧トップは消さない**：`home.html` はファイルとして残す（削除も改変もしない）。
2. 切替の実体は `vercel.json` の rewrite **1行だけ**：
   ```
   { "source": "/", "destination": "/home.html" }   ←→   { "source": "/", "destination": "/hub.html" }
   ```
   `"/index.html"` の行も同様に1行。
3. **戻し方**：この destination を `/home.html` に戻して push するだけ（デプロイ1〜2分）。データは一切動かないので副作用ゼロ。
4. 切替後も `/home.html` と `/hub.html` は**両方とも直接URLで開ける**（どちらが表かを変えるだけ）。
5. Vercel 側の即時ロールバックも可（`isRollbackCandidate` の直前デプロイへ戻す）。**ただし通常は 3 の1行戻しが確実**（他の変更を巻き戻さないため）。

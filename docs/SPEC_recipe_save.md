## 0. レシピとは（方針ver.6の心臓）

```
 1回目： 直す（AIに聞く） → ★差分プレビュー★ → 書き込む
                                   ↓
                        ★この直しに名前を付けて残す＝レシピ★
 2回目： レシピを選ぶ → ★差分プレビュー★ → 書き込む   ← ★AIを呼ばない★
```

**2回目からAIを呼ばない**、が全部。だから設計の芯は次の2つだけ:

1. **直しを「もう一度 同じように当てられる形」で残せるか**
2. **当て先を機械で見つけられるか**（＝来月の同じファイルの、同じ場所）

## 2. レシピの中身（★差分プレビューで見せている物 と同じ★）

`lib/diff-preview.js` の `build()` が既に作っている物を、そのまま残せばよい。
**新しい概念を足さない**（見せている物と残す物が違うと、見た物と別の物が当たる）。

```
レシピ = {
  名前:        人が付けた名前（例「1,234 を数に直す」）
  作った日:    いつ
  元のファイル: 名前とシート構成（当て先が同じ形かを見るため）
  直し[]:      1件ずつ
}
直し 1件 = {
  どのシート:  シート名
  どの列:      ★上の①②③のどれで当てるか★ ＋ その手がかり
                ① { 当て方:'列名', 名前:'時数' }
                ② { 当て方:'かたまり+列名', かたまり:'7月', 名前:'実車距離' }
                ③ { 当て方:'分かりません', 理由:'同じ列名が12個在り かたまりの名前が無い' }
  どの行:      「見出しの次から 中身が在る所まで」／「この1行だけ」
  何を:        ★式か 値か★（差分プレビューと同じ区別）
                式  → 直す前の式 と 直した後の式（相対参照のまま残す）
                値  → 直す前の値 と 直した後の値
  なぜ:        1行の説明（AIが言った言葉ではなく ★人が読める言葉★）
}
```

- **★式は「行ごとの答え」ではなく 式のまま残す★**。1行目の式だけ残して
  「その列の中身が在る行に 相対参照のまま当てる」＝ Ctrl+D と同じ考え方（実Excelで測った動きに合わせる）。
- **★当てる範囲は 行番号で焼き付けない★**。来月は行数が変わる。
  「見出しの次から 中身が在る所まで」で持つ。

## 4. 残す・選ぶ・別のブックに当てる

### 残す
- **★保存したレシピは消さない★**（成果物・電帳法）。
  画面に「削除」を出さない。名前の付け替えだけ許す。
- 置き場所は **倉庫（Supabase）の Exally の部屋**。
  ★倉庫はデータのため・コードは配信のため。ここは混ぜない★

### 選ぶ
- 開いているブックに対して **当てられそうなレシピだけ** を出す
  （シート名が1つも合わなければ出さない＝出来ない物のボタンを出さない）

### 別のブックに当てる
- **①②で当てられた所だけ当てる。③は当てない。**
- 当てられなかった所は **★「分かりません」と一覧で見せる★**（黙って飛ばさない）
- **★当てる前に必ず 差分プレビューを出す★**（新しい窓は作らない・同じ窓を使う）

## 5. 画面（★新しい窓を作らない★）

差分プレビューの窓に **行を1本 足すだけ**:

```
  ┌─────────────────────────────────────────┐
  │ 18か所 書き換わります                    │
  │  … （今と同じ中身）…                     │
  │                                         │
  │ ★この直しに名前を付けて残す★  [名前____] │  ← 足すのはここ1行
  │                                         │
  │ 書き出す名前 [代行計算表2026.xlsb____]    │
  │            [やめる]  [書き出す]          │
  └─────────────────────────────────────────┘
```

- 名前を空のままなら **残さない**（今までと1文字も変わらない動き）
- レシピを当てる入口は **「読み込む」の隣ではなく、直した後の同じ窓**
  ＝ ★別ウィザードを作らない★

## 6. ★測りました（実物3つ・2026-08-21）★

指示役が場所を見つけてくれたので、**3つの実物を 本番と同じ道で開いて数えた**（読むだけ）。

| 何 | ファイル | 大きさ | 更新 |
|---|---|---|---|
| 去年まるごと | OneDrive / ZEROact税理士 / 2025 / 代行計算表2025.xlsb | 859,937B | 2026-01-05 |
| 2026年 2月の姿 | OneDrive / ZEROact税理士 / 2026 / 代行計算表2026.xlsb | 335,590B | 2026-02-04 |
| 2026年 8月の姿（今の物） | デスクトップ `代行計算表2026.xlsb` | 379,042B | 2026-08-15 |

**★原本は1バイトも触っていません★**（sha256 が 前後で同じ・複製は scratchpad）
```
 代行計算表2025.xlsb  CC15DFC8…4287  更新 2026-01-05 15:26:35（前後 同じ）
 代行計算表2026.xlsb  045C54B2…B10C  更新 2026-02-04 22:03:36（前後 同じ）
```

### ① ★列名は ズレる★

| くらべた物 | 結果 |
|---|---|
| 2026-02 → 2026-08（**同じ年の中**） | 給料表・売上表・月別 は **列名が同じ**。ただし **シートが 7枚→14枚 に増えた**（給料4〜8・計算・入力・距離 が増え、歩合 が消えた） |
| 2025 → 2026-08（**年をまたぐ**） | **★給料表の列名が入れ替わる★**（渡部豊・渡部良子 が消え、結田航平・正岡卓・向垣内 が増える＝**人名が列名**）／**月別が 6列→11列 に増える**／売上表だけ 48列で同じ |
| 給料1〜8 | 見出しに見えた物は **「◯月分」と日付シリアル**＝**毎月 変わる／そもそも見出しではない** |

**⇒ ★同じ年の中なら 列名で当てられる。年をまたぐと 人名の列は入れ替わる★**

### ② ★月のかたまりは 増えない。増えるのは「シート」★

売上表は 2025 / 2026-02 / 2026-08 とも **48列で同じ**＝12か月ぶんが最初から在る。
増えるのは **シートの方**（給料1〜3 → 給料1〜8）。
**⇒ 「◯番目のかたまり」を使わない判断は正しかった。代わりに ★シートが増える★ 事に備える。**

### ③ ★「分かりません」になる列が 何本・何%か★

| 本 | 列 | ①列名で当たる | ②かたまり+列名 | **★③分かりません★** |
|---|---|---|---|---|
| 2026年 8月（今の物） | 302 | 96 | 48 | **158（52%）** |
| 2026年 2月 | 302 | 33 | 0 | **269（89%）** |
| 2025年 | 325 | 38 | 0 | **287（88%）** |

**⇒ ★列名だけで当てられるのは 3〜4割。半分以上は「分かりません」★**
（古いファイルほど悪い。計算・入力・距離 が無いため）

### ④ ★「毎月 同じ直しが何回 出るか」＝機械で数えられる範囲では 0件★

うちが**今 直せると分かっている物**を3つとも数えた（判定は本番と同じ関数を呼んだ）。

| 直し | 2025年 | 2026-02 | 2026-08 |
|---|---|---|---|
| A **1,234 のように数が文字のまま**（`TypedValue.parseTyped`） | **0** | **0** | **0** |
| B **#REF! などのエラーが答えとして残っている** | **0** | **0** | **0** |
| C **表の名前での参照**（Table[列名]） | 39,260 | 15,770 | 11,669 |

- **A と B は 実物に1件も無い**。E3（1,234）は **仕様から作った直しで、司さんの実物には出ていない**。
- **C は毎回 大量に出るが、これは ★読み込む時に自動で直している★**＝レシピに残す物ではない。
- **⇒ ★「レシピに残す価値のある 繰り返しの直し」を 実物から1件も見つけられませんでした★**

**★ただし これは「機械で数えられる3種類」の話です★**
司さんが毎月 実際にどんな直しをしているか（式を書き換える／列を足す／数字を打ち直す）は
**ファイルを見ても分からない＝★人に聞くしかない★**。

**⇒ 出す物: ★レシピを作る前に「先月、この表で どこを直しましたか」を1つ聞く★**
それが1つでも出れば、その形に合わせて作る。出なければ **★作る順を後ろへ下げる★** のが正しい。

## 7. この設計で ★やらない★ と決めた事（理由つき）

| やらない | なぜ |
|---|---|
| 「◯番目の列」で当てる | 月が増減した瞬間に **黙って別の列を書き換える**。#ERROR より悪い |
| レシピを消せるようにする | 成果物・電帳法。★保存レシピは消さない★ |
| 当てる前に見せずに当てる | 方針ver.6の②「直す前に必ず見せる」に反する |
| 当てられない所を「たぶんここ」で当てる | ★分かりません と出す★（指示役の決まり） |
| 新しいウィザード画面 | ★聞いてあげる。埋めさせない★／別ウィザード禁止 |

# P2でグリッドを作り直す時に、必ず設計へ入れること（実測済みの入力）

作成 2026-08-01 / 出所＝版対応 検証ハーネスの実測（`tests/xlsx-harness/`）

台帳（`known-diffs.json`）の注記は「今こうなっている」の記録で、**設計の時に拾われない**。
ここは「**次に作り直す時、設計の入力として必ず考えること**」だけを置く。

---

## 1. ★スピル（配列が隣のセルへ溢れる）— 製品判断が要る

**実測（2026-08-01）**

| 式 | Exally（今のグリッド） | 実Excel |
|---|---|---|
| `=C1:C6*E1:E6` | **100**（1セルだけ） | **100** ＋ **6セルを占有** |
| `=IF(D1:D6="A",E1:E6,0)` | **100**（1セルだけ） | **100** ＋ **6セルを占有** |
| `=SORT(E1:E6)` | 先頭のみ | 6セルを占有 |

- **値（左上）は Excel と一致している。** ズレているのは「隣へ溢れるかどうか」だけ。
- 今は `SUM()` `COUNT()` `TEXTJOIN()` などで包めば正しい答えが出るので、**実害は出ていない**。
- 台帳では**区分C（期限なし）**。直すかどうかは実装の都合ではなく**製品判断**だから。

**設計時に決めること**

1. スピルを**入れるのか入れないのか**。入れないなら、配列を返す式を単セルに書いた人に
   「左上しか出ません」と**画面で伝えるか**（黙って1個だけ出すのが一番危ない）。
2. 入れるなら、①占有範囲の描画 ②`#SPILL!`（既に何か入っている所へ溢れる時）③スピル範囲の参照（`A1#`）
   の3つが要る。**①だけ入れると②③が無いぶん Excel と挙動が食い違う**。
3. どちらでも **ハーネスに「占有セル数」を比べるケースを足す**こと（golden には `spillCells` を記録済み）。

---

## 2. ★セルに打ち込んだ物の解釈（入力パーサ）

**実測**：Excel は標準書式のセルに打ち込むと解釈するが、うちは文字列のまま持つ。

| 打ち込んだ値 | Exally | 実Excel |
|---|---|---|
| `1,234` | 文字列 `1,234` | **数値 1234** |
| `2026-07-31` | 文字列のまま | **日付 46234** |
| `0007` | 数値 7（一致） | 数値 7 |
| `007-1234` | 文字列（一致） | 文字列 |

- `1,234` が数値にならない＝**以降の合計に入らない**。お金が静かに落ちる。
- 台帳では区分A・期限 2026-09-30。**関数プラグインでは直らない**（`book.html` の入力処理の話）。

**設計時に決めること**：入力パーサを「Excelと同じ順番で試す」形にする
（数値 → 桁区切り付き数値 → 日付 → 時刻 → 論理値 → 文字列）。**書式（表示形式）を持つ設計かどうか**もここで決まる。
書式を持たないなら `0007` を文字列で保持する手段が無い（Excelは「文字列」書式で保持できる）。

## 3. ★Excelへ書き出す時の「動的配列の印」

**実測**：SheetJS が書いた xlsx を Excel で開くと、**配列を返す式が旧来の解釈になる**。

| 式 | グリッド画面 | 書き出したファイルをExcelで開いた時 |
|---|---|---|
| `=SUM(C1:C6*E1:E6)` | 97100 | **#VALUE!** |
| `=SUM(IF(D1:D6="A",E1:E6,0))` | 1000 | **#VALUE!** |
| `=COUNT(IF(...))` | 6 | **0** |

- 原因＝セルに「動的配列である」印（`cm` 属性とメタデータ）が要るが、SheetJS が書いていない。
- 今は実害ゼロ（グリッドの Excel 保存は未接続）。**書き出しを繋ぐ前に必ず解決すること。**
- 台帳 `file_roundtrip_known`（区分A・期限 2026-09-30）。

**設計時に決めること**：書き出しの唯一の口（`xlsx-io.js`）で
①印を書けるようにする ②書けないなら**配列式を含むブックは書き出し時に警告する**（黙って壊れた物を渡さない）。

---

## 4. 既に解決済みだが、作り直す時に落とさないこと

| 項目 | 中身 |
|---|---|
| **`_xlfn.` の付与** | XLOOKUP / IFS / TEXTJOIN / SORT / UNIQUE / FILTER 等を素の名前で書くと **Excelがファイルごと開けない**。`xlsx-io.js` が書き出しで付け、読み戻しで外す。**37関数を1つずつ実Excelで確認済み** |
| **LET / LAMBDA** | 引数名にも `_xlpm.` が要る。未対応なので**書き出しを止める**（壊れたファイルを作らない） |
| **関数の定義場所** | 入れ子で使われうる純粋関数は **HFプラグイン**、セルを直接読むグリッド固有のオペだけ `_jsSet`。両方に居たらCIが赤 |
| **配列演算** | `buildEmpty` に **`useArrayArithmetic: true`** が要る（無いと `(範囲="A")*範囲` が潰れて SUMPRODUCT が狂う） |

---

## 5. 残っている構造課題（設計の前提として知っておくこと）

- **入れ子で答えが変わる関数が 38 個**残っている（`_jsSet` 側・第3波）。
  `nesting-audit.mjs --probe --check` が baseline を超えたらCIが赤になる仕掛けは入っている。
- **キー操作**は別の棚卸し（`tests/keys-harness/`）。**Delete が範囲を消さず左上1個だけ**、
  **グリッド→Excel のコピーが片道**の2つは、グリッドを作り直すなら同時に直す対象。

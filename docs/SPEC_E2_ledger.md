## 1. ★調査で分かった事（実物ベース）

### 1-1. K2 の期間定義は実装済み（`payslip-app/lib/periods.js`）
```
METHODS = ['monthly','half','ten','ndays']
monthly → [P1(1〜末)]                  ※分割なしでも key は 'P1'
half    → [P1(1-15), P2(16-末)]
ten     → [P1(1-10), P2(11-20), P3(21-末)]   ← 代行はこれ（月3回）
ndays(n)→ [P1, P2, ...] n日ごと・端数は最終期間
```
末日・うるう年は `new Date(y,m,0)` で正確。**Exallyはこの定義に1ミリも足さない/変えない**。

### 1-2. ★E0契約とのズレ（要修正）★
E0 `SPEC_shared_schema.md` §6-2 では月次1本を **`M`** と定義したが、`periods.js` は**分割なしでも `P1`**。
→ **決定**：`pay_payslips` の id は
- **分割なし（monthly）＝従来どおり `ps_{ym}_{eid}`（period を付けない）**＝既存データと完全互換
- **分割あり（half/ten/ndays）＝ `ps_{ym}_{P1|P2|P3...}_{eid}`**
- `data.period` には **`periods.js` が返す key をそのまま**入れる（monthly なら `'P1'`）。
→ E0 SPEC §6-2 の「`M`」表記を上記に**改訂する**（Kyuallyセッションにも申し送り）。

### 1-3. 締め方の設定は既に Kyually にある
`payslip-app/js/app.js:324 defCompany()` に **`shimeMethod`（monthly/half/ten/ndays）** と **`shimeN`**。
保存先は `pay_companies.data.company.*`。
→ **Exallyは `pay_companies` を読むだけ**（E0 §3で「書かない」と決めたが**読みは禁止していない**）。
**締め方のUIをExally側に作らない**＝二重管理を作らない。Exallyには「今の締め方：10日締め（給料明細アプリの会社設定で変えられます）」と**表示だけ**。

### 1-4. ★台帳→給料の接続点は `pay-rule.js` の ctx★
```
ctx = { workMin, workDays, sales, commission, count }
```
`rate`（売上×率%）・`daily`（日給×出勤日数）・`piece`（単価×件数）・`max`（AかBの高い方）等がこれを食う。
**司さんの代行＝「売上×0.35 と 保障 の高い方」＝ `mode:'max'` そのもの**（Kyuallyに実装済み）。
→ **E2の出口＝この ctx を期間ごとに作ること**。これが「台帳→期間集計→給料が一本」の実体。

### 1-5. Kyually 側の日別入力（`dailyEntries`）との差
| Kyually `dailyEntries` | Exally `pay_ledger.data` | |
|---|---|---|
| `ymd` | `ymd`（列） | 同じ |
| `hm`（"8:30"の文字列） | `minutes`（分） | 変換が要る |
| `amount` | `amount` | 同じ |
| `count` | `count` | 同じ |
| `hikazei`（非課税フラグ） | **無い** | ★§4で追加 |
| **無い** | `uriage`（売上） | 率で払う代行に必須 |

## 3. 画面（逆Excル・モバイル前提）

### 3-1. 台帳（ハブの「日次台帳」が本物になる）
```
┌──────────────────────────┐
│ 日次台帳            2026年7月 ▼ │
│ 締め方：10日締め（月3回）        │  ← Kyuallyの設定を表示だけ
├──────────────────────────┤
│ [1〜10] [11〜20] [21〜末]        │  ← 期間タブ(periods.jsが返す)
├──────────────────────────┤
│  鈴木 花子   代行                │
│  ¥13,100 ／ 3件 ／ 5時間30分     │
│                        ＋入れる →│
├──────────────────────────┤
│  山田 太郎   空調                │
│  ¥306,000 ／ 2件                 │
│                        ＋入れる →│
└──────────────────────────┘
```
- **人ごとに1枚のカード**。その期間の合計が常に見えている（＝締めた時いくらか、が毎日見える）。
- 「＋入れる」で**1件の入力**へ。

### 3-2. 1件の入力（白紙の表を埋めさせない＝逆Excル）
```
┌──────────────────────────┐
│ 鈴木 花子 に入れる               │
│                                  │
│ いつ    [今日] [きのう] [7/3 ▼]  │  ← チップで選ぶ(既定=今日)
│ 事業    [代行] [空調] [その他]   │  ← 事業マスタから(実データ接地)
│                                  │
│ 売上    [      4,200 ] 円        │  ← 大きい数字キー
│ 時間    [ 1:30 ] [+30分][+1時間] │
│ 件数    [ 1 ] [－][＋]           │
│ メモ    [                    ]   │
│                                  │
│              [やめる] [入れる]   │
└──────────────────────────┘
```
- ★**同じ日にもう1件**を続けて入れられる（②）。入れた直後に「もう1件入れる」を出す。
- 出す項目は**その会社が使うものだけ**（売上を使わない会社に売上欄を出さない）。使う項目は§3-4。
- `data-kiku="ledger-entry"` の差し込み口だけ置く（E3で「言うだけ」を載せる）。

### 3-3. その日の一覧・直し
日付をタップ→その日の行が並ぶ（1日複数行が見える）。行タップで直す／削除（**ソフト削除**）。

### 3-4. 使う項目の決め方（項目を増やしすぎない）
`pay_org.data.ledgerFields`（新設・既定 `['uriage','count','minutes']`）で、その会社が使う欄だけ出す。
※これは**Exallyの持ち物**（`pay_org`）なので Kyually と衝突しない。

### 3-5. 期間の締め（出口）
期間タブに「この期間を締める」→ **人ごとの ctx** を出す。
```
鈴木 花子（1〜10）
  売上 13,100 ／ 出勤 3日 ／ 労働 5時間30分 ／ 件数 3 ／ 手入力の歩合 0
  → 給料明細アプリへ（この数字で計算されます）
```
- **Exallyは金額を計算しない**（§5）。出すのは**実績値**だけ。
- 「給料明細アプリへ」＝Kyuallyを開く（K4で自動取り込み）。

## 4. データ（①）— `pay_ledger` に1キーだけ追加提案
```
data = { uriage?, minutes?, amount?, count?, business?, memo?, hikazei? }
```
★**`hikazei`（非課税・真偽）を追加**。理由＝Kyuallyの `dailyEntries` が持っており、無いと **K4 で読み替えた時に非課税の区別が落ちて課税額が狂う**（お金の間違い）。
DDL変更は不要（jsonb）。E0 SPEC §5 に追記する。

**出勤日数（workDays）の定義**：その期間に**1行でもある日の数**（同じ日に3件あっても1日）。
※「実際に働いた日」の意味。テストで固定する。

## 5. ★支給額を Exally で計算しない理由（⑤・要判断）★
- 決め方（時給/日給/率/段階/AかBの高い方）は **Kyually の `pay-rule.js`（120行・実装済）** が持つ。
  設定（`payRule`）も **従業員data＝Kyuallyの持ち物**。
- Exallyにコピーすると**ドリフト事故**（最賃38県の誤値と同じ形）。`periods.js`(62行)は突合で守れるが、
  `pay-rule.js` は分岐が多く、突合で守るのが割に合わない。
- よって **E2の出口は ctx（実績値）まで**。金額は Kyually が出す。

★**ROADMAP E2 の受け入れ条件は「期間の支給額が出る」**。上記だと **Exallyの画面には金額が出ない**（実績値のみ）。
→ **司さんの判断が要る所**：
  - **(A) 実績値まで**（推奨・二重実装ゼロ・K4で金額が出る）
  - **(B) 金額もExallyで出す**（`pay-rule.js` も突合テスト付きで持つ。手間とドリフト危険が増える）

### B. テストが進んでいる 18件＋テストのみ 14件 ＝ **32件**
第3波と版対応。**中身としては要る。**

- 版対応ハーネス … `tests/xlsx-harness/` 13件＋`cases/90〜92`（P1〜P3）
- グリッドのExcel書き出し … `lib/grid-xlsx.js`／`lib/excel-version.js`／`lib/xlsx-io.js`＋各テスト
- `exally-formula.js`／`book.html`／`docs/SPEC_wave3_p1_plugin_migration.md`

**`tests/xlsx-harness/xlsx-io.js`（本番）と `lib/xlsx-io.js`（テスト）は同じ物。**
二重に作ったのではなく、**P2でグリッドが実際に呼ぶ時に `lib/` へ移す**と決めてあった移動。
本番へ持ってくる時は **staging側（`lib/`）の場所を採る**。

## どう合わせるか（★実行は指示役のOK後★）

**stagingを作り直さない。本番へ足す＋stagingを本番に追従させる。**
理由: 差の内訳がA(33)とB(32)でほぼ同じ大きさで、どちらかを捨てると片方の作業が消える。

### 手順（★指示役の判断で ①と②を入れ替えた・2026-08-05★）

**なぜ「本番→staging」が先か**
- **B には司さんが承認していない新機能（グリッドのExcel保存）が入っている。**
  先に本番へ出すと、司さんが1度も見ないまま本番に出る。
- **「足すだけだから壊れない」は成り立たない。**
  2026-08-02、掃除でファイルを消したら `api/claude.js` が require していて
  **本番のチャットが7日間500**だった。足す方向でも読み込み順・名前の衝突・CIの重さは変わる。
  → **失敗してよい場所（staging・客が使っていない）で先にやる。**

**① A を staging へ（本番→テスト）… 完了**
**② 差を測り直す … 完了（65 → 38）**
**③ B を本番へ … ★承認を分ける★**
- 版対応ハーネス（本番に一部入っており、承認済みの筋）→ 出してよい
- **グリッドのExcel保存（`saveXlsx` / `grid-xlsx` / `excel-version`）→ 司さんに見せてOKをもらってから**
- **1コミットに混ぜない。**

**④ 差を0にして固定** … `check-parity` を週1の `hosts` ワークフローに同居させる。
通常CIには入れない（相手のリポジトリを見るので、外の都合で赤くなるため）。

### （参考）当初案 — 「Bを本番へ」を先にする順番。★採用しない★

1. **B を本番へ持ってくる**（テスト→本番）
   `tests/xlsx-harness/` 一式・`lib/{grid-xlsx,excel-version,xlsx-io}.js` とそのテスト・
   `exally-formula.js`・`book.html`・SPEC。
   `tests/xlsx-harness/xlsx-io.js` は消して `lib/xlsx-io.js` に寄せる（呼び出し側も直す）。
   → 本番CIに版対応ハーネスの行を足す。**緑を確認してから次へ。**

2. **A を staging へ持ってくる**（本番→テスト）
   給与の見た目と渡し方・守り12本の `exit(1)` 化・拾えているかの確認・
   本番にしか無い守り4本・入口の見張り3本（**staging側の古い3本は捨てて本番版で置き換える**）。
   `js/supa-config.js` と `manifest.json` 系は**触らない**（倉庫と配信先が違う）。

3. **差を 0 にして固定する**
   `check-parity` を 週1の `hosts` ワークフローに同居させ、**差が出たらその週に気づく**ようにする。
   通常CIには入れない（相手のリポジトリを見るので、外の都合で赤くなるため）。

## これ以降の決まり（指示役・2026-08-05）

1. **片方だけに入れて終わらない。** 入れたら必ずもう片方の扱いを決めて書く。
2. 「本番だけでよい」「stagingだけでよい」なら **その理由を報告に書く**。
3. **差が10件を超えたら新しい作業に入らない。**
4. 報告に **「差 N件」を毎回載せる。**
5. **★何かを作る前に `node scripts/check-parity.mjs` を1回走らせる。★**
   片側にしか無い物は「もう作られている」可能性がある。
   入口の見張りを2回作ったのも、代行請求の動く実物を探さなかったのも、同じ形の間違い。

# キー操作ハーネス（★まだ台帳だけ・実装していない）

Excel を触ってきた人がグリッドで同じ手が使えるか。
指示役が本番グリッドで Excel ショートカット30通りを実測した結果を、**台帳としてだけ**置いてある。

**ここにはまだ自動検証はない。作るのは P2。** 今回は登録のみ（実装するなという指示）。

## 今わかっていること（2026-07-31 実測）

| 区分 | 件数 | 中身 |
|---|---|---|
| Excelと同じ | 12 | 個別の一覧は未記録（件数だけの報告だった） |
| 入っているが挙動が違う | 8行 | Ctrl+↓ / Ctrl+Shift+↓ / **Delete が範囲を消さず左上1個だけ** / Ctrl+D / Ctrl+R / Enter が編集開始 / Escape でコピー範囲が解除されない / PageDown 無効 |
| 未実装 | 10 | Ctrl+F / Ctrl+H / Ctrl+1 / F4 / Ctrl+; / Ctrl+Space / Shift+Space / Ctrl+"+"-" / Shift+F11 / Ctrl+PageUp・PageDown |
| 別件 | 1 | グリッド→Excel のコピーが片道（`ctxCopy` が OS のクリップボードに書いていない） |

> 数え方の注: 指示役の集計は「違う=7個」。ここでは挙がったキーを1つずつ行にしたので8行になる
> （Ctrl+↓ と Ctrl+Shift+↓、Ctrl+D と Ctrl+R のまとめ方の違い）。中身は同じ。ハーネスを作る時に揃える。

## 作る時の形（関数ハーネスと同じにすること）

`tests/xlsx-harness/` と同じ骨格にする。

- **golden = Excelの仕様**（何が正しいか）。ここは実Excelの挙動を1つずつ確かめて固定する
- **台帳（known-diffs.json）＋期限**。区分Aは期限必須・期限切れは赤
- **self-test**。わざと壊して赤くなることを毎回確認する
- **未検証を緑と呼ばない**

## 優先して直したいもの（台帳の money_impact）

- **Delete が範囲を消さず左上1個だけ** … 消したつもりが残る＝データが中途半端になる
- **グリッド→Excel のコピーが片道** … 「Excel落とし」の入口として効く。
  関数側の `xlsx-io.js` と同じく「唯一の口」を作る形にすること
